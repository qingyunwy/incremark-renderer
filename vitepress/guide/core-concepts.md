# 核心概念

## Stable Blocks 和 Mutable Tail

渲染器会把当前输入拆成两部分：

- `stable blocks`：已经闭合、不会再变化的块
- `mutable tail`：最后一个仍可能继续增长的片段

这样做的好处是，历史部分一旦稳定就不再重复 `lexer`，后续只需要处理新稳定的块和尾部片段。

## 为什么这比“每次全量重跑”更稳

朴素方案通常会在每个 chunk 到达时重新解析整篇 Markdown，这会带来几个问题：

- 文档越长，每次更新越贵
- 段落、列表、代码块未闭合时会反复抖动
- DOM 容器被整体替换，导致闪烁和滚动位置不稳定

`incremark-renderer` 的设计目标，就是尽量让这些成本和抖动只留在最后那一小段可变尾部。

## Render Patches

每次更新会输出块级 patch：

- `insert`：新增可见块
- `replace`：已有块内容发生变化
- `remove`：已有块从可见区移除

这个 patch 既适合框架层消费，也适合直接驱动浏览器局部 DOM 更新。

## 浏览器侧是怎么减少重绘的

浏览器 API `IncrementalDomRenderer` 会把 patch 应用到 root 容器：

- 不变的块保持挂载
- 变化的块按 key 做 replace
- 结构足够接近时会尝试原地同步属性和文本

这也是 demo 页里 patch 日志、块快照和最终渲染可以同时成立的原因。

## 扩展能力

库本身除了基础渲染链路，还内置了几类常见生产能力：

- `highlight.js` 代码高亮
- `katex` 数学公式
- `:::` 自定义容器
- 默认开启的 HTML 安全清洗
- 打字机播放与光标跟随

这些能力都可以按需关闭或替换，不会强制绑死在某一种 UI 形态里。
